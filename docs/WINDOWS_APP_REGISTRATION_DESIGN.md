# Windows 대상 앱 직접 선택·등록 설계 검토

이 문서는 후속 기능의 설계안입니다. 이번 변경은 Orca 기본 지원과 호환 이전만 구현하며 사용자 앱 등록 UI는 추가하지 않습니다.

## 1. 난이도와 범위

현재 코드는 PowerShell 5.1 + WPF이며 대상은 `settings.json`의 `targets`와 `appMultipliers`입니다. 설정창의 고급·진단은 목록을 읽어 보여 주고, 실제 렌더러는 시작 시 두 값을 별도 변수에 저장합니다. 따라서 UI에서 JSON만 바꾸면 실행 중인 렌더러에는 반영되지 않습니다. 기존 설정창의 임시 편집·충돌 검사·원자적 저장·실패 복구까지 연결해야 합니다.

실행 중인 일반 데스크톱 앱 선택 MVP는 **난이도 중간**, 미실행 앱/스토어 앱/권한 예외까지 포괄하면 **중간~높음**으로 판단합니다. 이는 현재 코드와 Windows API 동작을 바탕으로 한 추정이며 실제 프로토타입을 만든 일정은 아닙니다.

| 작업 | 예상 개발/검증 노력 | 이유 |
|---|---|---|
| 실행 중인 창 후보 수집·선택 UI | 1~2일 | 실제 창과 소유 프로세스 구분, 중복 제거, 종료 경합 처리 |
| 대상 추가/삭제/배율·저장·실시간 반영 | 1~2일 | 임시 편집과 충돌, 저장 실패 시 이전 상태 유지 |
| 자동 회귀·실기기 검증·문서 | 1~2일 | Electron 다중 프로세스, 여러 창, 최소화, 앱 전환, 접근 거부 |
| 선택: EXE 파일로 미실행 앱 등록 | 추가 1~2일 | 파일명과 실제 창 프로세스가 다른 앱 처리, 경로 예외 |

범위가 확정된 1인 개발의 대략적 추정으로 MVP 3~6일이며 환경·완성도에 따라 달라집니다. 새 의존성/SDK/API 서비스 없이 기존 WPF와 Windows 내장 API로 구현 가능합니다.

## 2. 추천 사용자 흐름

설정창에 **대상 앱** 영역을 추가하고 기존 등록 목록·배율·삭제와 **실행 중인 앱에서 추가** 버튼을 제공합니다. 창 제목은 후보 식별에만 잠깐 표시하고 저장하지 않습니다. 사용자가 앱을 선택하면 `표시 이름 / 실제 ProcessName / 기본 배율 1.0` 미리보기를 확인합니다. 기존 대상이면 새로 중복 등록하지 않고 해당 항목으로 이동합니다.

선택 결과는 임시 편집 상태로 보관하며 **적용 및 저장**에서만 확정합니다. 대상 앱 창을 다시 활성화하면 즉시 효과를 확인할 수 있어야 합니다. 설정창이 전경인 동안 대상 앱 효과가 나타나지 않는 이유를 안내하면 검증 혼동을 줄일 수 있습니다.

후보가 없으면 앱을 열고 새로 고침하도록 안내합니다. 첫 MVP는 실행 중인 일반 데스크톱 앱만 지원하고, EXE 탐색은 별도 후속 범위로 둡니다. 창 선택을 가장한 임의 파일 실행은 하지 않습니다.

## 3. 후보 수집과 실제 매칭

후보 수집은 [EnumWindows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows)로 최상위 데스크톱 창을 열거하고, 보이는 창·유효 영역·식별 가능한 표시 이름을 가진 후보를 우선 표시합니다. 자신의 Desktop/Bridge와 창 없는 백그라운드 프로세스는 제외합니다. HWND별로 [GetWindowThreadProcessId](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowthreadprocessid)를 호출해 실제 창 소유 프로세스를 조회합니다. 최종 저장 전에 HWND/PID를 다시 조회해 종료·재사용 경합을 확인합니다.

단순한 `Get-Process` 전체 목록은 Electron helper와 백그라운드 서비스를 많이 포함합니다. `MainWindowHandle`은 캐시되고 GUI가 없으면 0일 수 있으므로 후보 보조 정보로만 사용합니다. 여러 창이 있는 앱은 HWND별 후보에서 동일 ProcessName을 묶어 보여 주되 런타임에는 항상 실제 전경 HWND를 사용합니다. [Microsoft MainWindowHandle 설명](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.mainwindowhandle?view=netframework-4.8.1)을 참고합니다.

실제 렌더링은 현재의 전경 HWND → PID → 소문자 ProcessName → 대상 목록 → 창 영역 경로를 재사용합니다. 제목 일치·앱 설치 여부·프로세스가 살아 있다는 사실만으로 효과를 표시하지 않습니다. 프로세스명 등록은 같은 이름의 모든 실행 파일에 적용되는 시각 효과 규칙이며 실행 파일의 신뢰성 검증을 뜻하지 않습니다.

권한이 다른 앱·창 종료·시스템 호스트 앱은 개별 후보만 건너뛰거나 선택 불가 사유를 표시하고 목록 전체를 실패시키지 않습니다. 관리자 실행을 요구하거나 다른 앱 권한을 변경하지 않습니다. Windows 스토어 호스트/다른 실행 파일명/런처 앱은 선택 화면에서 실제 프로세스명을 보여 주고 후속 실기기 검증 대상으로 분리합니다.

## 4. 호환 저장과 런타임 갱신

첫 MVP는 기존 `targets: string[]`와 `appMultipliers: object`를 유지합니다. 별도 규칙 스키마·실행 경로·PID·HWND·제목 저장은 필요하지 않습니다. ProcessName만 저장하므로 PID 재사용과 설치 경로 변경에 덜 의존하며 기존 설정/페어링은 그대로 읽을 수 있습니다.

1. `Set-AmbientLocalControl`에 대상 추가/삭제/배율을 위한 검증된 로컬 패치를 추가합니다. 대상 이름은 빈 값·경로·`.exe` 혼동을 정규화하고 대소문자 중복을 제거합니다. 배율은 기존 실제 적용 범위 0.5~1.5 안에서 허용합니다.
2. 추가는 기존 배열 끝에 하나만 넣고 삭제는 지정한 항목만 제거합니다. 사용자가 등록한 다른 이름·배율과 알 수 없는 필드를 보존합니다. 삭제한 배율은 재등록 시 복원할지 UI 정책을 먼저 확정합니다.
3. 기존 `Copy-AmbientControlConfig` → 후보 검증 → `Save-AmbientSettings` 경로를 사용합니다. 성공 후 `Apply-DesktopLocalControl`에서 `targets`/배율의 런타임 컨테이너를 갱신합니다. 기존 이벤트 콜백이 `GetNewClosure()`로 시작 시 변수를 캡처하므로 단순 변수 재대입 대신 공유된 `$targetRuntime` 객체의 필드/컬렉션을 교체하는 방식이 필요합니다. 저장 실패 시 메모리 대상과 실제 표시도 이전 상태로 유지합니다.
4. 설정창에 대상 목록용 기준값과 임시 패치를 추가해 같은 대상이 외부에서 변경되었을 때 충돌을 표시합니다. 선택/새로 고침만으로 저장하지 않습니다. 저장 직후 삭제한 앱이 전경이면 오버레이와 영상 레이어를 즉시 숨깁니다.
5. 이번 Orca용 `targetDefaultsVersion=1`을 유지합니다. 이후 사용자 삭제를 기본값 이전이 다시 덮지 않도록 새 기본 앱은 별도 이전 번호로 해당 앱만 추가합니다. 이전 번호는 사용자 일반 설정의 스키마/제품 버전과 구분합니다.

EXE 파일 선택은 실행 없이 파일명으로 후보를 만들 수 있으나 실제 창 소유 프로세스와 다를 수 있습니다. 이 경우 임시 등록 후 실제 전경 프로세스 확인 단계를 제공해야 합니다. 실행 경로별 매칭이 필요해지면 별도 규칙 스키마와 경로 조회 실패 정책을 설계하며 첫 MVP에 함께 넣지 않습니다.

## 5. 후속 구현의 수락 기준

- 창 없는 helper 제외, 여러 창/동일 앱 후보 중복 정리, 선택 도중 종료·접근 거부 처리.
- 일반 앱·Electron 앱의 실제 전경 ProcessName으로 등록되고 재시작 뒤 유지.
- 기존 target 문자열·사용자 배율·페어링 키와 Orca 이전 표시 보존.
- 추가/삭제/배율 적용 즉시 렌더러 갱신, 저장 실패 시 UI·파일·실제 표시의 일관성 유지.
- RGB만·영상만·둘 다·OFF, 미지원 앱 전환, Pause/Resume, 최소화/복귀 회귀.
- 후보 탐색에 사용한 제목·경로·아이콘을 진단 로그나 영구 설정에 자동 저장하지 않음.

추천 순서는 **현재 Orca 실기기 수락 → 실행 중인 앱 선택 MVP → EXE 선택과 특수 앱 보완**입니다. Orca 지원을 위해 일반 등록 UI나 추가 SDK를 먼저 도입할 필요는 없습니다.
