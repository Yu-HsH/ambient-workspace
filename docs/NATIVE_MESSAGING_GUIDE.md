# Chrome 연결 등록과 기존 설정 보존

단일 사용자용 `1.0.0-rc.1` 공개 테스트 RC의 사용자 절차입니다. 개인 Windows 계정·ACL PASS 로컬 NTFS 설치만 지원하며 실제 두 계정 접근 실험은 미수행입니다. 제품은 HTTP로 자동 돌아가지 않습니다. Chrome Web Store·관리자 권한 없이 현재 Windows 사용자의 HKCU에 연결 경로를 한 번 등록합니다. 이 등록 때문에 폴더 이동 뒤 재등록이 필요합니다.

## 새로 설치하는 경우

1. 신뢰 가능한 후보 ZIP 전체를 짧은 개인 로컬 NTFS 폴더에 풉니다. 실제 ACL 검사를 통과해야 합니다. Desktop과 Browser 폴더를 함께 보관합니다.
2. `Desktop_Companion/Start.bat`을 실행합니다. 설정의 연결 탭 → **Chrome 연결 등록**, 또는 `Desktop_Companion/Setup-Chrome.bat`으로 등록 창을 엽니다.
3. Chrome `chrome://extensions` → 개발자 모드 → 압축해제된 확장 프로그램 로드에서 `Browser_Extension`을 선택합니다. 배포용 후보 ZIP의 고정 ID는 `ncbcjbbidoaallpikijfbjdmijjljhoe`입니다. 다른 ID이면 처음 등록을 진행하지 말고 후보 파일을 확인하세요.
4. 확장 팝업 → **Windows 연결**에서 등록용 ID를 복사해 Desktop 등록 창에 붙이고 **처음 등록**을 누릅니다. 현재 사용자 등록만 만들며 Windows 기본 .NET 컴파일러로 작은 host 실행 파일을 생성합니다. Node·Python·새 SDK 설치는 필요 없습니다. 기본 컴파일러 또는 조직 정책 때문에 실패하면 원인 코드를 표시합니다.
5. Desktop의 페어링 코드를 팝업에 저장하고 실제 연결 검사를 합니다. **코드 저장됨**은 연결 성공 표시가 아닙니다. Desktop 상태가 확인되는지 확인하세요. 코드는 Native Messaging의 표준 입출력으로만 전달되고 디스크 명령 큐에는 남기지 않습니다.
6. YouTube를 명시적으로 연결하고 Windows 색/영상 전송을 선택합니다. 통합 pause/resume 뒤 실제 효과와 개별 OFF 유지도 확인합니다.

등록 확인은 경로·파일 검사입니다. 실제 Chrome 통신 성공을 대신하지 않습니다. 고정 ID의 공개 키는 서명·배포자 인증서가 아닙니다. 신뢰 가능한 제품 파일과 실제 ACL이 함께 필요합니다. 이 공개 소스와 RC ZIP에는 같은 고정 ID용 manifest.key를 포함합니다. 예전 key 없는 ID의 저장소를 자동 합치지 않습니다. 최초 설치는 신뢰한 전체 RC ZIP을 사용하세요.

## 기존 Desktop 설정과 키

Desktop과 Chrome 캡처를 종료합니다. 원본 `settings.json`, 필요 시 `settings.json.bak`, `bridge-pairing.txt`를 비공개 백업한 후, 신뢰 가능한 새 개인 폴더의 `Desktop_Companion`에 **첫 실행 전에 복사**합니다. 기존 폴더·키·로그를 삭제하지 않습니다. 새 폴더를 먼저 실행하면 별도 키가 생길 수 있으므로 순서를 지키세요. 이미 파일이 있으면 덮어쓰기 전에 양쪽을 보존하고 앱을 종료하세요.

복사 전후 권한을 확인합니다. 예전 PS1/BAT/XAML/실행 파일이나 runtime JSON/JPEG는 가져오지 않습니다. 키 값이 보존되면 재페어링할 필요가 없습니다. 이미 노출된 키·공유 사본은 새 설치만으로 회수되지 않습니다.

## 예전 확장 ID의 Chrome 설정 가져오기

키 없는 예전 확장은 경로에 따라 ID가 달랐습니다. 예전 ID를 새 host의 허용 목록에 추가하거나 예전 코드를 실행해 백업하지 않습니다. 원본 확장 저장소의 닫힌 복사본을 신뢰 가능한 도우미에서 읽습니다. **개인 데이터 이전은 사용자가 아래 순서로 수행합니다. 자동 이전하지 않습니다.**

1. 예전 Chrome에서 `chrome://version`의 **프로필 경로**와 `chrome://extensions`의 예전 확장 ID를 비공개로 기록합니다. 예전 확장을 **비활성화**하고 캡처를 중지합니다. 제거하면 설정을 잃을 수 있으므로 아직 제거하지 않습니다. 예전 확장이 실행 중이면 과거 HTTP 경로도 계속 남을 수 있습니다.
2. Chrome 창을 모두 종료합니다. 원본 프로필을 쓰는 Chrome이 계속 실행되면 이전을 진행하지 않습니다.
3. 새 Desktop 등록 창 → **이전 확장 설정 준비**에서 `Default`/`Profile 1` 같은 원본 프로필 폴더와 예전 ID를 지정하고 **복사본 준비**를 누릅니다. 원본 ACL·잠금·파일 목록·크기·복사 전후 해시를 검사합니다. 원본 프로필과 예전 제품 코드는 수정하지 않습니다. 파일 권한이 불안전하면 거부하며 자동 권한 수정을 하지 않습니다.
4. **도우미 폴더 복사** → **도우미 Chrome 열기**를 누릅니다. 새 개인 Chrome 프로필의 `chrome://extensions`에서 개발자 모드를 켜고 복사한 도우미 폴더를 수동 로드합니다. 도우미는 복사본의 설정을 개인 백업에 저장하고 완료 여부만 표시합니다. 로그인·기존 방문 기록·쿠키를 옮기지 않습니다.
5. 도우미가 저장 완료를 표시하면 이 별도 Chrome을 종료하고 **백업 확인·이전 완료**를 누릅니다. 검증한 백업을 새 Desktop에 복사한 뒤 이 작업의 임시 host 등록을 해제합니다. 원본·준비 폴더·백업은 보존합니다.
6. 본래 사용할 Chrome에서 고정 ID의 새 확장을 로드하고 위의 사용자별 등록을 완료합니다. 캡처를 끈 상태에서 팝업 → **기존 확장 설정 가져오기·백업** → **백업 목록 읽기**로 이전 백업을 선택합니다. 시각·항목 수를 확인하고 확인 상자를 체크한 뒤 **선택한 설정 복원**을 누릅니다. 원문 키·설정은 목록에 표시하지 않습니다.
7. 복원 직전에 현재 확장 설정을 별도 백업하며, 원본에 없는 현재 항목은 유지합니다. 저장 후 읽어서 확인하고 실패하면 이 작업의 변경만 되돌립니다. 복구까지 실패하면 성공으로 표시하지 않습니다. 기존 페어링·일반 설정·알 수 없는 추가 필드 보존을 확인한 뒤 YouTube 캡처를 다시 연결합니다. 예전 확장을 제거하는 결정은 확인 후 사용자가 합니다.

백업에는 페어링 복사본이 포함될 수 있습니다. 제품 루트의 `migration-*` 준비 폴더와 Desktop의 `native-profile-backups`를 공유·Git 등록하지 마세요. 원본 프로필의 ACL이 차단되거나 데이터가 손상된 경우 파일을 보존하고 중단합니다. 원본을 덮어쓰거나 키를 재발급해 우회하지 않습니다.

## 폴더 이동·업데이트·등록 실패

| 상황 | 절차 |
|---|---|
| 전체 폴더 이동 | Desktop·Chrome을 종료하고 이동합니다. 새 위치 ACL 검사 후 Setup-Chrome.bat → **이 폴더로 재등록**. Chrome의 확장 경로도 새 위치로 로드합니다. 고정 ID와 같은 Chrome 프로필이면 저장소를 이어 쓰는지 확인하고, 옛 항목 제거 전 백업하세요. |
| 업데이트 | 개인 파일을 비공개 백업하고 종료 후 신뢰 가능한 제품을 풉니다. **이 폴더로 재등록**으로 새 host 소스를 반영합니다. 등록 중 실패하면 원래 파일·등록을 복구하도록 기록을 남깁니다. |
| 다른 위치가 등록됨 | **처음 등록**은 충돌을 거부합니다. 사용할 위치를 확인한 다음 **이 폴더로 재등록**을 명시적으로 선택합니다. |
| 파일 잠금/중단 | Chrome 종료 후 재시도합니다. 복구 필요 표시가 있으면 **실패 이전으로 복구**를 사용합니다. 작업 중 제3자가 등록/파일을 바꿨으면 덮어쓰지 않고 복구 실패를 표시합니다. |
| 이전 과정 중단 | **기존 준비 기록 열기**에서 해당 `migration.json`을 선택합니다. 완료를 재확인하거나 **임시 등록만 해제**합니다. 보존된 파일은 자동 삭제하지 않습니다. |
| 오래된 ID | `NATIVE_LEGACY_MIGRATION_REQUIRED`는 위의 복사본 이전 절차가 필요하다는 뜻입니다. 허용 ID를 임의로 넓히지 마세요. |
| 경로가 너무 김 | `NATIVE_PATH_TOO_LONG`: 개인 파일을 보존하고 더 짧은 개인 로컬 경로에 신뢰 가능한 제품을 풉니다. 다시 ACL 검사·재등록합니다. |
| 등록/파일 권한 거부 | `NATIVE_REGISTRY_SECURITY`, `NATIVE_REGISTRY_ACCESS_DENIED`, `NATIVE_FILE_SECURITY`를 기록하세요. 관리자 실행·Users/Everyone 권한 추가로 우회하지 않습니다. 조직 정책이면 담당 관리자에게 문의합니다. |

## 등록 해제와 보안 경계

Desktop·Chrome을 종료한 뒤 해당 폴더의 Setup-Chrome.bat → **등록 해제**를 사용합니다. 이 폴더를 가리키는 현재 사용자 등록만 해제하며 다른 등록을 덮어쓰거나 설정·키·백업을 지우지 않습니다. 이미 연결된 host는 Chrome 종료 뒤 끝납니다. 이후 확장 제거·개인 파일 보관/삭제는 사용자가 별도로 결정합니다.

등록은 `HKCU\Software\Google\Chrome\NativeMessagingHosts\org.ambientworkspace.bridge`에 저장합니다. 32/64비트 조회 경로와 상위 키의 실제 ACL도 확인합니다. host 소스·생성 실행 파일·manifest·허용 origin·등록 복구 기록은 `Desktop_Companion`에 남습니다. 파일 읽기 보호와 스크립트/등록 변조 보호를 함께 검사합니다. 설치 폴더 전체나 시스템 ACL을 일괄 변경하지 않습니다.

Native Messaging은 Chrome이 허용된 ID와 로컬 host를 표준 입출력으로 연결합니다. 새 worker/offscreen/Bridge에는 localhost HTTP 송신·리스너·자동 fallback이 없습니다. 페어링 검증 전 RGB/JPEG·제어 명령은 거부하며 비밀값은 명령 파일에 기록하지 않습니다. 영상/제어 기밀성은 OS 프로세스·파일 접근 경계에 의존하고 별도 디스크 암호화를 제공하지 않습니다. 동일 사용자 악성 프로세스·관리자·SYSTEM·공용 Windows 계정은 보호 범위 밖입니다. 실제 두 일반 계정 로그인 접근 시험은 미수행이며 이번 RC 필수 조건에서 제외했습니다. 지원은 개인 Windows 계정·ACL PASS 로컬 NTFS 설치로 제한하고 향후 검증 과제로 유지합니다. 공용 계정·공유 폴더·조직 정책 환경의 안전성을 보장하지 않습니다.

Chrome 공식 문서: [Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging), [고정 확장 ID의 key](https://developer.chrome.com/docs/extensions/reference/manifest/key).


## 연결 확인 시 함께 볼 항목

### Chrome 재시작 후 웹만 연결되고 Windows 전송이 시작되지 않을 때

Native 준비 확인이 실패하면 YouTube·웹 캡처는 연결돼도 해당 세션의 Windows 송신은 시작되지 않을 수 있습니다. 팝업을 다시 열면 **Windows 전송이 시작되지 않았어요** 안내를 확인할 수 있습니다. 기다리거나 팝업을 다시 여는 것만으로 송신이 자동 복구되지 않습니다.

1. Desktop 트레이 실행·확장의 **Windows로 전송**·**흐릿한 영상도 전송**·Desktop의 개별 RGB/영상·통합 pause 상태를 확인합니다.
2. 영상·페이지 로딩을 마친 뒤 팝업 상단 **취소·해제**로 연결을 끊고 YouTube 탭에서 **YouTube 연결**을 다시 누릅니다. 기존 키·설정은 유지합니다.
3. 실제 Desktop 상태와 색상·영상 출력을 확인합니다. 등록 확인·코드 저장만으로 송신 복구를 판단하지 않습니다.
4. 계속 실패하면 등록 창의 읽기 전용 **등록 확인**으로 경로·ID·오류 코드를 확인한 뒤 위의 등록 실패 절차를 따릅니다. 자동 재페어링·설정 초기화·관리자 실행으로 우회하지 않습니다.

이 안내는 관측된 세션의 복구 절차이며 Native 지연·공유 연결 취소 자체의 영구 해결을 뜻하지 않습니다. [FAQ](FAQ.md)와 [Known Issues](KNOWN_ISSUES.md)에 기존 실패 기록과 제한을 유지합니다.

### 일반 연결·성능 확인

페이지와 영상 로딩이 완료된 상태에서 팝업의 현재 연결 상태를 확인한 뒤 명시적으로 연결하세요. 시작 실패 때 기존 키·설정을 지우거나 재페어링하지 않습니다. source 이동/레이아웃 변경 중의 취소와 정상 연결 뒤 끊김은 구분해 오류 문구만 기록하세요. 새 후보에서 로딩 완료 상태 시작/중지10회는 통과했지만 앞선 간헐 시작 실패의 원인은 확정하지 않았습니다.

JPEG는 내부 Worker로 변환하며 기본/실험 FPS 수치는 상한입니다. 실제 ACK와 WPF 표시 속도는 서로 다르고, 실험5/10FPS 달성을 보장하지 않습니다. 정상 연결 뒤 개별OFF·pause/resume·직접 키보드 단축키·재시작·설정/키 보존을 실제 환경에서 확인하세요. 등록·기존 프로필 이전은 사용자가 원본과 백업을 보존한 상태에서 명시적으로 수행합니다.
